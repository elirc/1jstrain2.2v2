# Stack Ready client audit and plan

Scope: everything under `client/src/` (App, main, lib, components, pages, styles.css), plus
`client/index.html`, `vite.config.ts`, `tsconfig.json`, and the server contract in
`server/src/routes/api.js` and `server/src/sessions.js`. Installed versions: React **19.3.0**,
react-router-dom **7.18.3**, Vite **7.3.6**. That matters because `useEffectEvent` (stable since
19.2) and document-metadata hoisting (`<title>` rendered from any component) are both available.

Method: I read every file and ran throwaway Node probes (in the scratchpad) over the real
curriculum (434 questions, 31 primers) to check which Markdown and tokenizer edge cases the
current content actually hits, and which are only latent. I computed contrast ratios from the
theme tokens. No project file was modified.

Severity scale: **Critical** means data corruption or a frozen tab. **High** means a core
flow is broken or misleading. **Medium** means a visible defect or accessibility failure.
**Low** means polish or a latent issue.

## 1. Bugs and correctness issues

### 1.1 Drill flow (pages/DrillPage.tsx)

**B1. "Another round" is inert, and it loses the session scope.** High.
`DrillPage.tsx:547-553`
```tsx
to={`/drill?mode=${session.mode}${moduleId ? `&moduleId=${moduleId}` : ''}&n=${Date.now()}`}
reloadDocument={false}
```
The fetch effect's deps (`:70`) are `[profile, mode, moduleId, trackId, stageId, limit]`. `n` isn't
read anywhere. Navigating to the same route with only `n` changed re-renders `DrillPage` without
remounting it (same route element, same tree position). `index` stays at
`session.questions.length`, so the Summary stays up and nothing is fetched. The learner clicks
and nothing happens except the URL. For track and stage sessions, the link also drops
`trackId`/`stageId`. If it did refetch, the server would answer 400 `unknown track: undefined`
(sessions.js:43). `reloadDocument={false}` is already the default, so it does nothing.

Fix (pick one):
- **Preferred:** keep a `round` counter in the drill reducer (§3, A3). "Another round" becomes a
  button that dispatches `restart`, and the fetch effect depends on `round`. No URL games.
- Quick fix: have the route render `<DrillRoute/>`, which returns
  `<DrillPage key={useLocation().key} />`. Build the link with `drillHref()` from
  `session.moduleId/stageId/trackId` (the server echoes them back).

**B4. The window-level keydown handler is too greedy.** High (a11y and correctness).
`DrillPage.tsx:253-289`
```tsx
if (target && (target.tagName === 'INPUT' || target.tagName === 'TEXTAREA')) {
  if (event.key === 'Enter' && !answered) submit();
  return;
}
if (event.key === 'Enter') { event.preventDefault(); if (answered) onNext(); else submit(); return; }
if (answered) return;
const digit = Number(event.key);
```
Here is what goes wrong:
1. **Enter on any focused button or link anywhere on the page is stolen.** That includes the
   up/down reorder buttons (`OrderList`), topbar `NavLink`s, the ThemeToggle, and the error-state
   links. Pressing Enter on a focused nav link mid-question *submits the answer and does not
   navigate*. On an order question, keyboard users can only move items with Space, because
   Enter submits the current order.
2. **The Shell's "new learner" input counts as an `INPUT`.** Typing a name there and pressing
   Enter also calls the drill's `submit()`.
3. **No modifier check.** `Ctrl+1`/`Cmd+1` (switch browser tab) and `Alt+digit` are
   `preventDefault`ed whenever the digit is within the choice count.
4. **No `event.repeat` guard.** Holding Enter submits, then autorepeat calls `onNext` as soon as
   `answered` flips, which skips the explanation (the whole teaching payload).
5. **Digits are handled on `order` questions** (`count = choices.length`). They toggle a
   `selection` that `order` never reads, and `preventDefault` still runs.
6. **`SELECT` isn't excluded.** Enter on the profile `<select>` submits.
7. **Listener churn and stale-closure window.** `submit` is recreated whenever
   `selection`/`text`/`ordering` changes (`response` is a dependency, `:245`), so the listener is
   removed and re-added on every keystroke in the short-answer box. The churn is cheap, but the
   gap between a state change and re-registration is what makes B13 possible.

Fix: handle keys only when focus is in the card or on `<body>`, and read the latest state through
`useEffectEvent` (available in React 19.3):
```tsx
const onKey = useEffectEvent((e: KeyboardEvent) => {
  if (e.defaultPrevented || e.repeat || e.ctrlKey || e.metaKey || e.altKey) return;
  const t = e.target as HTMLElement;
  if (t !== document.body && !cardRef.current?.contains(t)) return;   // nav, topbar keep their keys
  if (e.key === 'Enter') {
    if (t.closest('a, select, button:not(.choice)')) return;          // native activation wins
    e.preventDefault(); answered ? onNext() : submit(); return;
  }
  if (answered || !isChoiceType(question.type) || t.closest('input, textarea')) return;
  // digit handling ...
});
useEffect(() => {
  const h = (e: KeyboardEvent) => onKey(e);
  window.addEventListener('keydown', h);
  return () => window.removeEventListener('keydown', h);
}, []);
```
Wrap the card in a `<form onSubmit>` so Enter in the short-answer input works natively. That
removes the `INPUT` special case altogether.

**B13. Double submission is possible.** Medium.
`DrillPage.tsx:228-245`. The only guard is `if (!canSubmit) return`, where `canSubmit` is
render-time state captured in the closure. Two activations (Enter autorepeat, or Enter plus a
click) that arrive before the `submitting` re-render both POST `/answers`. The server has no
idempotency (api.js:108-144), so the learner gets two attempts: double XP, and the SRS schedule
advances twice. Fix: a synchronous `inFlight` ref (or the reducer guard in A3) plus B4's
`e.repeat` guard. Optionally send a client `attemptId` and have the server dedupe.

**B14. Focus and scroll after grading and advancing.** Medium (mobile UX, a11y).
- `:248-250` `nextButton.current?.focus()` scrolls the viewport to the button at the very bottom.
  With a long `why` on a phone, the "Correct / Not quite" header scrolls off the top. Use
  `focus({ preventScroll: true })` and `feedbackRef.current?.scrollIntoView({ block: 'nearest' })`.
- **Screen readers never hear the verdict.** Focus lands on "Next question, button", and the
  feedback block has no live region. Put the verdict in a region that exists before grading,
  with `role="status"` (polite).
- When the next question mounts, scroll position stays where the previous Next button was, so
  the new prompt can be off-screen above. On advance, scroll `.drill` into view and move focus
  to the prompt `<h2 tabIndex={-1}>`.

**B7. Order questions: no correct order shown, the shuffle can be pre-solved, and focus is lost.**
Medium.
- `:336-340`: `correct` is one boolean. A wrong answer turns the whole list red, and **the
  correct sequence is never displayed**. The learner can only reverse-engineer it from `why`.
  Fix: after grading, render the correct order (`result.answer as number[]` mapped to choice text)
  beside theirs, with a per-position check or cross.
- `:193-195` `shuffled(n)` can return the identity permutation. Order questions have 3, 4, 4, 4,
  4 and 6 items, so `web-browser-3` arrives already solved 1 time in 6, and `canSubmit` is true
  without touching anything. Fix: reshuffle while the permutation is the identity and `n > 1`.
- `OrderList` `key={`${item}-${i}`}` (`:471`) includes the index, so every move remounts both
  swapped `<li>`s and **keyboard focus drops to `<body>`** after each up/down press. Fix: key by
  the original choice index (the value in `ordering`), restore focus to the moved item's button
  through a ref map, and announce the move politely ("moved to position 2 of 4").
- The `aria-label` `Move "${item}" up` embeds raw Markdown backticks. Strip the Markdown.

**B15. Profile switch mid-session leaks an in-flight verdict into the new session.** Low-Medium.
The session effect (`:49-70`) resets state and refetches when `profile` changes, and the old
`QuestionCard` unmounts. But its `api.answer(...)` promise still resolves and calls
`onAnswered`, which runs `DrillPage`'s `setVerdicts`/`setXp`, and `DrillPage` is still mounted.
The new session starts with a phantom verdict (segment 0 is coloured, and the Summary counts are
off). Fix: stamp async results with `round` and drop stale ones (A3), or abort on unmount (A2).
Also, switching learner mid-drill silently discards the session. Confirm when
`index > 0 && !finished`.

The effect also depends on the `profile` **object**. Today its identity is stable because
`profiles.find` returns the same element, but any future `listProfiles()` refresh would restart
a live session. Depend on `profile?.id`.

**B16. Progress refresh is tied to the Summary effect.** Low (dev) / Medium (UX).
`:521-523` `useEffect(() => { void onFinish(); }, [onFinish])`. Under StrictMode
(`main.tsx:11`) dev fires it twice (two GET `/progress`). Production runs it once, so that part
is hygiene. The real problem is the opposite: **progress only refreshes if the learner reaches
the Summary.** Answer 7 of 12, then click "Roadmap", and the dashboard, nav due badge, module
bars and stage unlocks all show pre-session numbers until a reload. Fix: refresh from the event
path, after each graded answer (coalesced) and on drill unmount if anything was answered. Delete
the effect.

**B12. Duplicate questions inside one daily session.** High (server), with a client symptom.
`sessions.js:92`
```js
const out = [...shuffle(due).slice(0, reviewShare)];
...
for (const q of shuffle(due).slice(reviewShare)) {   // :101 - a second, independent shuffle
```
These are two different shuffles, so the tail can repeat questions from the head. It triggers
when `due.length > ceil(size/2)` and unseen plus shaky questions can't fill the session, which
is exactly an advanced learner with a large review queue. The learner answers the same card
twice in one sitting, and it's scheduled twice. Client side, `key={session.questions[index].id}`
(`DrillPage.tsx:163`) means adjacent duplicates reuse the already-answered `QuestionCard`
(`result` still set). Fix on the server: shuffle once and dedupe by id. Client defense in depth:
`key={`${index}:${id}`}`.

**B17. `limit` and `mode` parsing.** Low.
`:39` `Number(params.get('limit') ?? 12)`. `?limit=abc` gives `NaN`, which serializes to `null`.
The server does `Number(null) || 12`, which is 12, and React's `Object.is` dependency compare
treats `NaN` as equal to itself, so there's no refetch loop. That makes it benign today, but it's
accidental. Parse explicitly: `clampInt(raw, 1, 40, 12)`. `:35` casts `mode` without
validation. `?mode=foo` becomes a raw server 400 ("mode must be one of: ...") in the error banner.
Validate against `MODE_LABEL` keys in a `parseDrillParams` (A5).

**B18. Wrong keyboard hints.** Low.
`:435` renders "1-4 choose" for `short` (`choices` undefined gives `?? 4`) and for `order`, where
digits do nothing useful. Show "Enter submit" for `short`, and "Tab / Space to move" for `order`.
Hide the hint row on touch devices (`@media (hover: none)`).

**B19. Choice semantics and screen-reader feedback.** Medium (a11y).
- `aria-pressed` toggle buttons (`:370`) announce "toggle button, pressed". Single-answer
  questions are radio semantics, and `multi` is checkbox semantics. Use visually-hidden native
  `<input type="radio|checkbox">` inside styled `<label class="choice">`. That gives arrow keys,
  grouping and state announcements for free, with less code.
- `<legend className="sr-only"><Inline text={question.prompt}/></legend>` (`:344-346`) makes
  screen readers read the prompt twice (the `h2`, then the legend). Put the `TYPE_HINT` there
  ("Select every correct answer").
- `<span aria-label="correct">✓</span>` (`:385-386`) is a generic element. ARIA 1.2 prohibits
  naming generics, and NVDA and VoiceOver ignore the label. After grading the choices are also
  `disabled`, so they drop out of the tab order. **A screen-reader user can't find out which
  choice was right.** Fix: visually-hidden text inside each choice ("correct answer",
  "your answer, incorrect"), and keep the choices focusable (`aria-disabled` or read-only)
  after grading.
- For `multi`, a correct choice you **missed** looks identical to one you picked (both
  `is-correct`). Add an `is-missed` state (dashed good border plus the word "missed"). It is the
  most useful signal on a select-all question.

**B20. The drill progress strip is colour-only.** Low.
`:144-151` is `aria-hidden`, which is fine given the visible "3 / 12". But correct and wrong
segments differ only in red and green. Add a non-colour cue (a hatched `background-image` on
wrong segments, or a taller correct segment), or expose it as `role="progressbar"` with
`aria-valuetext="question 3 of 12, 2 correct so far"`.

**B21. No "I don't know" or skip.** Medium (learning UX).
If `/answers` keeps failing (server restarted), the learner is stuck with only an error banner.
More importantly, there's no honest way to give up and see the explanation, so learners guess,
which pollutes accuracy and SRS. See P3.

### 1.2 App state and data loading (lib/app-state.tsx, App.tsx, lib/api.ts)

**B3. A stale stored profile id leaves the app permanently on an error screen.** High.
`app-state.tsx:43` seeds `profileId` from localStorage. The progress effect (`:90-107`) fires at
once with that id, in parallel with boot (`:51-79`). If the id no longer exists (data dir wiped,
`better-sqlite3` fell back to the JSON store as the README describes, which gives a different
profile table, or a fresh server re-seeding "Me" with a new id), the server answers **404 "No
such profile."** almost instantly (`requireProfile`, api.js:167-172). Boot is still waiting on
the ~95 KB `/curriculum` (modules including primers). The 404 lands first and calls `setError`.
Boot then correctly selects the first profile, but **nothing ever clears `error`**, so `Gate`
(`App.tsx:59-71`) shows "The API should be running on port 3001" forever. The message is also
wrong. Fix:
1. Don't load progress until boot has resolved the active profile.
2. Treat a 404 on progress as "forget this profile" rather than as fatal.
3. Clear errors on success.
Test 34 covers this.

**B5. Non-fatal errors are promoted to fatal.** High.
`refreshProgress` (`:86`) and the progress effect (`:102`) write to the same `error` that `Gate`
uses as its boot-failure switch. One failed refresh (the server restarted while you finished a
drill) replaces every page, including a half-read primer, with the boot error. There's no retry,
and the error never clears. Fix: separate `bootError` (fatal, with a Retry button that re-runs
boot) from progress status (keep the last good `progress`, and show a dismissible banner). See A6.

**B22. Refresh race across profile switches.** Low-Medium.
`refreshProgress` (`:81-88`) and `resetProgress` (`:123-127`) have no cancellation or identity
check. Sequence: the Summary calls `refreshProgress()` for A, and the user switches to B. B's
effect resolves, then A's response lands and `setProgress(A)` overwrites it. B's name is now shown
with A's numbers. Fix: check a `currentProfileIdRef` before setting, or move to `useResource` (A1),
which aborts superseded requests.

**B23. Blank screens while progress loads.** Medium.
`selectProfile` nulls `progress` (`:112`). Dashboard, Tracks and Progress `return null` while
`!progress` (`Dashboard.tsx:14`, `TracksPage.tsx:10`, `ProgressPage.tsx:17`), so after every
profile switch, and briefly on first load, the page body is empty with no indicator. `Gate` only
waits for curriculum and profiles. Fix: the Gate layout waits for the first `progress`. After
that, keep the previous value while reloading and show a subtle "updating" state, never `null`.

**B24. `useModuleProgress` fabricates a JS record.** Low.
`app-state.tsx:188-202` returns `trackId: 'js' as const` for any unstarted module, which is wrong
for 22 of 31 modules. Nothing reads that `trackId` today, but the zeroed fallback is **also
returned while progress is loading**, so ModulePage flashes "0 of N mastered · Start drilling"
for a learner who has mastered the module. Fix: return `ModuleProgress | null`, and render a
placeholder at the call site. If a default is really wanted, take `trackId` from `moduleById`.

**B25. Error boundary and `errorElement` placement lose the shell.** Medium.
`App.tsx:111-119` wraps `RouterProvider` in `Boundary`. But the data router's `errorElement` on
the Shell route (`:85`) catches render errors from every route first, and an `errorElement`
**replaces its route's element**, which is the Shell. A crash in (say) the Markdown renderer
therefore shows `RouteError` with no topbar, no nav, no link home and no retry. `Boundary` only
ever catches errors thrown by `AppProvider` itself. `RouteError` also ignores
`isRouteErrorResponse`. Fix:
```ts
{ element: <Shell/>, errorElement: <RootError/>, children: [
    { element: <Gate><Outlet/></Gate>, errorElement: <RouteError/>, children: [/* app routes */] },
    { path: '*', element: <NotFound/> },
]}
```
Now route errors render inside the Shell's `<Outlet/>`. `RouteError` offers "Try again" and
"Back to the roadmap". Keep `Boundary` as a router-independent last resort.

**B26. `Gate` is repeated per route.** Low (structure).
Six copies (`App.tsx:88-93`). One pathless layout route does the same job, and it's where B23's
progress wait and B25's error element belong.

**B27. No scroll restoration.** Medium.
`createBrowserRouter` without `<ScrollRestoration/>` keeps the window scroll offset across
navigations. Click a module card low on the roadmap, and the module page opens scrolled past its
header. Back-navigation doesn't restore either. Fix: render `<ScrollRestoration/>` once in
`Shell`. It's one line.

**B28. The API client trusts the envelope and the path.** Medium.
`api.ts:56-82`:
- `return body.data as T` (`:81`). If a 200 body isn't JSON (a production SPA fallback serving
  `index.html` for a missing API route, or a proxy page), `body` is `null`, and callers get
  `TypeError: Cannot read properties of null` instead of an `ApiError`. Check
  `body !== null && typeof body === 'object' && 'data' in body`, and otherwise throw
  `ApiError(..., status, 'bad_response')`.
- A `fetch` rejection (server down) surfaces as the raw "Failed to fetch". Map it to
  `ApiError('Cannot reach the Stack Ready API', 0, 'network')`.
- No `AbortSignal` support, so none of the pages' "cancellation" cancels anything. It only
  ignores the result.
- Ids are interpolated unencoded: `/modules/${id}` (`:94`) and `/profiles/${id}` (`:90`).
  `/module/..%2Fprogress` is decoded by `useParams` to `../progress`, which fetches
  `/api/progress`. That returns progress rather than a module, and `data.module.trackId` throws
  during render. Use `encodeURIComponent`.
- `...headers` (`:67`) silently drops a `Headers` instance. Type it as
  `Record<string, string>`.

**B29. Unhandled rejections in UI actions.** Low.
`Shell.onAdd` (`Shell.tsx:21-28`), the reset button (`ProgressPage.tsx:167-170`) and
`resetProgress` `await` without `catch`. A failure leaves the form or the "Yes, erase it" state
stuck with no message. Catch it and show an inline error. Also, Escape doesn't cancel the
add-learner form.

### 1.3 Markdown renderer (components/Markdown.tsx)

The probes show the current content uses none of the unsupported features: no links,
blockquotes, nested lists, hr, `~~~` fences, entities, or escaped characters. Bold-with-code (B8)
is the only live defect. The rest is latent, but B2 is severe enough that "latent" isn't
comfortable. **Recommendation:** pin the supported subset with tests (§4) and teach
`validateContent()` to reject anything outside it. Don't grow a CommonMark implementation.

**B2. Infinite loop on a `|`-leading line that isn't a table.** Critical (latent).
The table branch (`:95`) needs `line.trim().startsWith('|')` **and** a next line matching
`/^\s*\|[\s:|-]+\|\s*$/`. If the separator is missing, or is valid GFM without outer pipes
(`|---|---`, `---|---`), the table branch is skipped. The paragraph branch's `while` (`:155-163`)
then rejects the very first line (`!lines[i].trim().startsWith('|')`), so `paragraph` is empty,
**`i` never advances**, and `renderBlocks` spins forever. The tab freezes: on a module page for a
primer, or **mid-drill** for a `why`. Fix:
- The paragraph branch always consumes the current line (`do { ... } while (...)`).
- Relax the separator to GFM rules (cells `:?-{3,}:?`, outer pipes optional).
- Add a loop invariant: `if (i === start) i += 1;` after the dispatch.

**B8. Inline parsing is non-recursive, so bold containing code shows backticks.** Medium (live).
`:21` `/(`[^`]+`|\*\*[^*]+\*\*|\*[^*\n]+\*)/g`. The bold alternative accepts backticks, so
`**always `===`**` renders `<strong>always `===`</strong>` with literal backticks. There are
**7 occurrences** in the primers (`js-values`; `js-functions`: `**`new Fn()`**`,
`**`fn.call/apply/bind(obj)`**`, `**`obj.method()`**`, `**Plain `fn()`**` - the four `this`
rules). Fix: recurse `parseInline(inner)` for `<strong>`/`<em>`. Code spans stay terminal.

Other inline gaps (latent):
- `\*[^*\n]+\*` italicises any `a * b * c` in prose. Require flanking non-space characters:
  `\*(?=\S)([^*\n]*?\S)\*`.
- No double-backtick code spans, so a code span containing a backtick can't be written.
  Support `` (`+)([^`]|[^`][\s\S]*?[^`])\1 ``.
- No backslash escapes (`\*`, `` \` ``, `\|`).
- `splitRow` (`:177-184`) splits on every `|`, including inside code spans. A cell like
  `` `a || b` `` breaks the row. Split only on pipes outside backticks and not preceded by `\`.
- No links (0 in the content today). If they're added, emit `<a>` only for `https:`, `http:` and
  relative hrefs (never `javascript:`), with `rel="noreferrer"` on external links, so the no-XSS
  claim stays true.
- `renderBlocks` wraps already-keyed blocks in `<Fragment key={n}>` (`:174`). That's redundant.

Block-level gaps (latent):
- **Nested lists flatten.** In a bullet list, an indented `  - sub` matches `bullet` and becomes
  a sibling. In a numbered list, `   - sub` matches the continuation regex (`:139`) and is glued
  into the parent text as " - sub". Implement one level of nesting, or reject it in the validator.
- **The ordered-list start number is ignored.** `3. x` renders as 1, and a loose list split by
  blank lines restarts at 1. Pass `<ol start>`.
- **A fence inside a list item** (indented) is glued into the item text.
- **A bare fence defaults to `lang='js'`** (`:64`). Both bare fences in the content are not JS:
  an HTTP route table in `web-api-design`, and a SQL clause order in `data-sql`. Default to
  `'text'`.
- `#####`+ becomes a literal paragraph. There's no blockquote or hr. Document these as
  unsupported and have the validator reject them.

HTML and entities: every string is a React text child, so `<T>`, `<script>` and `&lt;` display
literally and safely. **There is no escaping bug.** Nothing is entity-decoded, which is correct.

### 1.4 Code highlighter (components/Code.tsx)

**B9. The bash `--` comment rule is wrong.** Medium (live).
`:57-60` `(char === '-' && next === '-' && (lang === 'sql' || lang === 'bash'))`. In bash, `--`
starts a long flag, not a comment. The `craft-git` primer's
`git push -u origin feature/order-filters --force-with-lease` renders the flag as an italic
comment. Fix: `--` is a comment only in `sql`. In bash, `#` is a comment only at the start of a
line or after whitespace (so `$#`, `${#a}` and `url#frag` survive). `//` never starts a bash
comment (`curl https://...` currently goes grey).

Per-language correctness (latent in the current content):
| Issue | Langs | Example | Fix |
|---|---|---|---|
| `'`/`"` strings run across newlines when unterminated | js/ts/jsx/tsx/csharp | JSX text `<p>Don't</p>` turns the rest of the snippet green | Stop `'`/`"` at `\n`. Only the backtick spans lines |
| Regex literals aren't recognized | js/ts | `s.replace(/'/g, '')` starts a string | `/` after `( , = : [ ! & \| ? { } ;` or at line start begins a regex until an unescaped `/` on the same line |
| C# verbatim and raw strings | csharp | `@"C:\dir\"` treats `\"` as an escape | For `@"`, the only escape is `""`. For `"""`, scan to `"""` |
| Identifiers include `.` (`:92`) | all | `this.state`, `base.Foo()` lose keyword colour | Treat `.` as punctuation, but keep `digits.digits` together |
| Number forms | all | `0xFF`, `1e6`, `.5`, `3.14f`, `100m` not coloured | `/^(0x[\da-f_]+\|\d[\d_]*(\.\d+)?(e[+-]?\d+)?)[a-z]*$/i` |
| Contextual words as keywords | js | `const set = new Set()` colours `set` | Drop `get set of from static` from the JS list, or accept it (cosmetic) |
| Missing keywords | csharp | `yield lock nameof required with when record` | Extend |
| Unknown `lang` falls back to JS keywords (`:36`) | any | `http`, `text`, `sh`, `diff` | Alias map (`sh`→bash, `cs`/`c#`→csharp, `http`/`text`→plain), and don't highlight keywords for unknown langs |
| SQL `''` escape | sql | `'it''s'` | Renders as two adjacent strings, which looks identical. Leave it |

Rendering and a11y:
- Every non-word character becomes its own `<span>` (`:98`), so a 30-line snippet is about
  1,000 spans. Merge adjacent plain tokens and emit unkinded text as plain strings.
- `(<span key={i}>{token.text}</span>) as JSX.Element` (`:116`) is a pointless cast, and both
  branches are the same element. Use `<span key={i} className={token.kind}>`.
- `<pre tabIndex={0} aria-label="js code sample">` (`:108`). `aria-label` on a role-less element
  is prohibited or ignored. Use `role="region" aria-label="Code sample, JavaScript"`. That keeps
  the focusable scroller (good for keyboard horizontal scrolling) identifiable.
- **HTML entities: no bug.** Tokens are text children, so React escapes `<` and `&`.

### 1.5 Theme (components/ui.tsx ThemeToggle, index.html, styles.css)

**B30. Wrong-theme flash on load.** Medium.
`ThemeToggle` applies `data-theme` in `useEffect` (`ui.tsx:119-128`), after React's first commit.
`index.html` has no pre-paint script. A learner who forced **light** on a dark OS first gets
the dark palette from `@media (prefers-color-scheme: dark)`, then a flip (and the reverse for
forced dark on a light OS). Fix: a blocking classic script in `<head>`:
```html
<script>
  try { var t = localStorage.getItem('stack-ready:theme');
        if (t === 'light' || t === 'dark') document.documentElement.dataset.theme = t; } catch (e) {}
</script>
```
The server sends no CSP today (no helmet or CSP header in `server/src`). If one is added, allow
this script by hash. See §5.1 for making the script always resolve the effective theme.

**B31. A forced theme doesn't set `color-scheme`.** Low-Medium.
`<meta name="color-scheme" content="dark light">` (`index.html:6`) with no CSS `color-scheme`
means native UI (the `<select>` dropdown list, scrollbars, autofill) follows the **OS**, not the
toggle. Forced-light on a dark OS shows a dark dropdown on a light page. Add
`color-scheme: light` on `:root` and `color-scheme: dark` in the dark block.

**B32. Unvalidated stored theme.** Low.
`(localStorage.getItem(THEME_KEY) as Theme) ?? 'system'` (`ui.tsx:113`). A stored `"blue"` gives
`next["blue"]`, which is `undefined`, then `setTheme(undefined)` and `data-theme="undefined"`,
and the button is dead from then on. Validate with an `isTheme` guard.

**P1. A Summary that reviews the session, plus "explain again" for misses (accept both, merged).**

## 3. Architecture and refactor proposals

**A1. `useResource`, one hook for the cancelled-flag effect pattern.** S · risk low.
The same 15-line pattern appears in `app-state.tsx` (×2), `ModulePage.tsx:25-43` and
`DrillPage.tsx:49-70`. `refreshProgress` and `resetProgress` need it but don't have it (B22).
```ts
type Resource<T> = {
  status: 'idle' | 'loading' | 'ok' | 'error';
  data: T | null;            // kept during reload, so no blank screens (B23)
  error: ApiError | null;
  reload(): void;
};
export function useResource<T>(
  key: readonly unknown[] | null,          // null = idle (e.g. no profile yet)
  load: (signal: AbortSignal) => Promise<T>,
): Resource<T>;
```
It uses one `AbortController` per run, aborted on key change or unmount, and ignores `AbortError`.
`load` is read through `useEffectEvent`, so inline lambdas don't churn dependencies. The key is
compared element-wise. **Reject** building caching or deduping into it: it stays a hook, not a
query library.

**A2. API client with `AbortSignal`, envelope validation and encoded paths.** S · risk low.
`request<T>(path, { signal, profileId, method, json })`:
- `encodeURIComponent` on ids.
- Network failure → `ApiError(code: 'network')`.
- A non-envelope body → `'bad_response'` (B28).
- Every `api.*` method takes an optional `signal`.
- An `isApiError(e, code?)` guard.
- Optional timeout via `AbortSignal.any([signal, AbortSignal.timeout(15000)])`, which the
  browsers Vite 7 targets support.

**A3. Split DrillPage (579 lines) into `pages/drill/` plus a `useDrillSession` reducer.** M ·
risk medium (the core flow, so land the tests first).
```
pages/drill/DrillPage.tsx       parse params → useDrillSession → layout
pages/drill/useDrillSession.ts  reducer + effects (load session, submit, refresh progress)
pages/drill/QuestionCard.tsx    prompt, code, answer widget switch, feedback; <form onSubmit>
pages/drill/ChoiceList.tsx      mcq/output/boolean/multi with native radio/checkbox (B19)
pages/drill/OrderList.tsx       stable keys, focus retention, correct-order reveal (B7)
pages/drill/ShortAnswer.tsx
pages/drill/Feedback.tsx        live verdict, why, ask, history line (P4)
pages/drill/Summary.tsx         per-question review (P1)
pages/drill/keys.ts             shortcut table + useDrillHotkeys (B4, P8)
pages/drill/params.ts           parseDrillParams / drillHref (A5)
```
```ts
type Draft =
  | { kind: 'choice'; picked: number[] }      // mcq, output, boolean, multi
  | { kind: 'text'; text: string }
  | { kind: 'order'; order: number[] };

type DrillState = {
  round: number;                                  // restart = new round (B1)
  status: 'loading' | 'ready' | 'error';
  session: Session | null;
  index: number;
  items: { draft: Draft; submitting: boolean; result?: AnswerResult; error?: string }[];
  xp: number;
};
type Action =
  | { type: 'loaded'; round: number; session: Session }
  | { type: 'failed'; round: number; error: string }
  | { type: 'edit'; index: number; draft: Draft }
  | { type: 'submit'; index: number }
  | { type: 'graded'; round: number; index: number; result: AnswerResult }
  | { type: 'submitFailed'; round: number; index: number; error: string }
  | { type: 'next' }
  | { type: 'restart' };
```
Every async result carries `round`, and the reducer drops stale ones (B15, and the B1 restart).
`submit` is a no-op when `submitting || result` (B13, without refs). `items[i].result` feeds the
Summary review (P1). The pure helpers `toResponse(question, draft)` and
`initialDraft(question, rng)` (the non-identity shuffle) are unit-tested. `finished` is derived
(`index >= questions.length`) rather than stored.

**A4. Route structure: layout routes, errors, scroll and titles.** S · risk low.
Covers B25, B26, B27 and B34. The root `Shell` renders `<ScrollRestoration/>`. A pathless
`<Gate><Outlet/></Gate>` layout carries its own `errorElement` and wraps all the app routes, and

**A5. Typed drill params helper.** S · risk low.
`parseDrillParams(sp): { ok: true; spec: DrillSpec } | { ok: false; error: string }`, with

**A6. Error-handling strategy.** S · risk low.
Three classes:
1. **Boot failure** (profiles or curriculum): a full-page Gate error with Retry.
2. **Page data failure** (a `useResource` error): an inline banner in place of the content, with

3. **Background or action failure** (progress refresh, reset, create profile): a toast or inline

Render crashes go to the in-shell `errorElement` (B25). `AppState.error` is replaced by
`bootError` plus `progress.status`.

## 4. Test strategy

**Setup**
- Dev deps: `vitest`, `jsdom`, `@testing-library/react`, `@testing-library/user-event` and
  `@testing-library/jest-dom`.
- A `test` block in `vite.config.ts` (with `/// <reference types="vitest/config" />`), or a
  separate `vitest.config.ts`:
  `{ environment: 'jsdom', setupFiles: ['./src/test/setup.ts'], css: false, restoreMocks: true }`.
- `src/test/setup.ts`: `import '@testing-library/jest-dom/vitest'` and `afterEach(cleanup)`.
- Scripts: `"test": "vitest run"` and `"test:watch": "vitest"`. Add the client test run to the
  root `npm run check`.
- **Fetch mock:** a small helper that routes `METHOD /path` to handlers returning envelopes, and
  records calls. MSW isn't needed at this size.
- **Router:** export the route array from `App.tsx`, and use `createMemoryRouter(routes,
  { initialEntries })` wrapped in `AppProvider`.
- **Keep the logic pure so most tests are unit tests.** Export `parseInline`/`renderBlocks` (or
  introduce a `parseMarkdown(src): Block[]` AST step with a thin render layer), and `tokenize`
  from Code.tsx. The drill reducer, `toResponse`, `initialDraft`, `parseDrillParams`,
  `relativeDay` and `buildHeatmap` are all pure.

**Named test cases**

*Markdown (`components/Markdown.test.tsx`)*

   (vitest `timeout: 200`) (B2).

## 5. Design system notes

**What's good:** tokens on `:root`, explicit dark mode in both directions, a single
`:focus-visible` ring, a global reduced-motion rule, `tabular-nums` on figures, and a restrained
palette. Keep all of it.

**Findings and cleanup**

1. **The dark palette is duplicated verbatim** (`styles.css:46-78` and `:80-110`, 33
   declarations twice). It will drift. Fix: make the B30 head script **always resolve** the
   effective theme (stored choice, or `matchMedia('(prefers-color-scheme: dark)')`, plus a change
   listener while on "system") into `data-theme="light|dark"`. Then the CSS needs exactly one
   dark block, `:root[data-theme='dark']`, and the media-query copy goes away. (A no-JS fallback
   is moot for a React app.)
2. **No type scale.** 14 inline `fontSize` values (8, 11, 11.5, 12, 12.5, 13, 13.5, 14, 15, 16,
   19, 20, 21) plus 15 CSS sizes from 11 to 27 px, including 14.5 and 15.5. Proposal: 7 steps.
   `--fs-2xs 11` (kbd, badges, the LEVEL label), `--fs-xs 12` (meta), `--fs-sm 13.5`
   (secondary), `--fs-md 15` (body), `--fs-lg 17` (card titles, drill prompt on mobile),
   `--fs-xl 20` (section heads, drill title), `--fs-2xl 26` (page h1). Mapping: 11.5→12,
   12.5→12 or 13.5, 13→13.5, 14/14.5→15, 15.5/16→17, 18/19/21→20, 22/24/27→26.
3. **No spacing scale.** 30+ unique padding and margin combinations (`13px 15px`, `11px 13px`,
   `12px 14px`, `12px 15px`...). Use a 4-px base: `--sp-1 4`, `--sp-2 8`, `--sp-3 12`,
   `--sp-4 16`, `--sp-5 20`, `--sp-6 24`, `--sp-8 32`, `--sp-12 48`. Add `--card-pad`
   (20 desktop, 16 at 640 px and below) and `--section-gap` (`--sp-6`), which replaces the
   22/26 px values scattered inline.
4. **Radii:** 2, 3, 4, 5, 6, 7, 8, 12 and 999 are all in use. Consolidate to
   `--radius-sm 5` (code, kbd, choice key), `--radius 8`, `--radius-lg 12` and
   `--radius-pill 999`.
5. **Motion:** 0.06, 0.12, 0.14, 0.22, 0.25, 0.4, 0.5 and 0.7 s with mixed easings. Tokens:
   `--dur-fast 120ms` (hover and press), `--dur-med 220ms` (enter, bars), `--dur-slow 500ms`
   (ring and progress fills), and `--ease cubic-bezier(.2,.7,.2,1)`. Move `Ring`'s inline
   `transition` into CSS. Keep the global reduced-motion rule.
6. **Colour semantics:**
   - Add `--focus` rather than reusing `--accent`.
   - Add `--on-accent`, `--on-good` and `--on-bad` for text on solid fills (the graded choice
     key currently uses `var(--bg)`, which is 4.08:1 in light).
   - Add `--track`, set per element through a custom property instead of inline `background`.
   - Apply the B11 values: `--text-faint` **must** pass 4.5:1 on `--bg-inset`, because it's used
     for body-size metadata.
   - Stop using `opacity` to express "locked".
7. **Focus rings:** the global rule sets `border-radius: 4px` (`:163-167`), which *changes the
   element's own radius* while focused (8 px buttons and 12 px cards visibly square off).
   Remove it, because outlines follow the element's radius in evergreen browsers. Restore the
   ring on `.input` (B11). Use `outline-offset: -2px` inside the tight `.choice` list so rings
   don't overlap neighbours.
8. **Elevation:** one `--shadow`, used only by `.card-hover`. Rename it to `--shadow-raised`,
   and add `--shadow-overlay` for the dialogs P8 and P9 introduce.
9. **Missing component classes** (from the inline-style audit): `.section-title`, `.meta`,
   `.list-row`, `.btn-block`, `.badge` (the nav count, currently `tag tag-accent` plus
   `marginLeft: 6`), `.toast`, `.skip-link` and `.skeleton`.
10. **Touch:** `@media (pointer: coarse)` gives 44 px minimum targets for `.btn-sm` and the
    order buttons. `@media (hover: none)` hides `.kbd` hints.
11. **Print** (P17): about 20 lines, and it forces the light tokens.

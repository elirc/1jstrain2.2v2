# ADR-0012: Test the server with one dependency-free self-test script

Status: **superseded by ADR-0016** (Vitest at the root; `check.js` stays as the smoke test, written with J01) · Date 2026-09-23
Retro-documented from 6f1bf43
Anchors: `server/src/check.js › check (L1–27 @ 6f1bf43)`, `server/src/check.js › store.close (L142–150 @ 6f1bf43)`, `package.json › check (L18 @ 6f1bf43)`

> **Superseded.** This record stays because the reasoning still explains why `check.js` exists and why it survives. ADR-0016 moves unit and integration tests to Vitest and keeps `check.js` as the production smoke test that runs under `npm ci --omit=dev`. Read this ADR for the original trade-off and ADR-0016 for what replaced it. Do not edit this file except to update this note. A superseded ADR is history, not a draft.

## Context
The server has five modules of real logic and no test framework. `npm run check` had to work on a fresh clone and on a production install without dev dependencies. Tests that need `better-sqlite3` must release the file handle before cleanup, because Windows will not delete an open SQLite file.

## Decision
We wrote one script. It validates the curriculum, then drives the grader, the scheduler, the store, progress and sessions end to end against a temporary data directory. It prints `ok` or `FAIL` per check and exits non-zero on any failure. It uses no dependencies.

  }

## Consequences
- Good: it runs anywhere Node runs, with no install beyond the workspace, and finishes in about three seconds on Windows with the SQLite backend (37 `ok` lines at the baseline).
- Cost: there is no isolation. One `store` and one profile flow through every section, so a failure early on can change what later checks see.
- Cost: it pins a bug. L69–73 schedules two correct answers with the same `now` and asserts mastery, which is exactly server B2 (register F-01). A faithful port would carry the bug into the new suite. That is why J01 marks it rather than porting it, and why J10 fixes it to use a `now` one day later.
- Cost: the JSON store's exit hook flushes into the directory the `finally` just deleted. On the fallback backend that prints an `ENOENT` trace after "All checks passed." and still exits 0 (server ST2, F-13; the server audit reproduced it).
- Cost: the prose drifted. The header says "`npm run check` runs it in CI", and there is no CI. The README says "40 assertions", and a passing run prints 37 checks (F-23).
- Forces on future work: only whichever backend loads gets tested. The fallback is exercised only on machines where the native build fails.

## Alternatives rejected (at the time)
- **Node's built-in `node:test`.** Viable, dependency-free, and it would have fixed isolation for free. The code records no reason it lost. Opinion: it was the better choice at the time.
- **Vitest or Jest.** Rejected by the header's own goal, "a dependency-free smoke test" (L1–2). `jstrain/` already uses Vitest (ADR-0013), so the cost was lower than it looked.

## Breaks first at
Contributors and test count. At about 40 checks one file is readable. At 200, with two backends and a clock to inject, it needs `describe`, fixtures and filtering. That is where ADR-0016 takes over.

Done. See ADR-0016.
